# 合同 AI 预审（Contract Review v1）

目标：把「合同体检」变成一次命令或一条飞书消息就能完成的事——**先给结论、再给原文依据、最后给改法**，法务只需要复核和拍板。

> 定位：AI 按固定清单体检 + 每条结论必须带原文引用 + 风险分级 + 修改建议。
> 不做法律意见，不替代法务，只把「容易漏的坑」一次性摆到桌面上。

## 1. 怎么用

```powershell
# 规则模式（零配置，先跑通）
python -m src.cli review-contract data/sample_contract.txt --rules

# 规则 + 大模型语义审查（.env 里配好 LLM_API_KEY 后自动启用）
python -m src.cli review-contract "D:\合同\某某采购合同.docx"

# 指定输出目录
python -m src.cli review-contract 合同.pdf --out out/my-contracts
```

支持格式：`.docx`、文字型 `.pdf`、`.txt`/`.md`。扫描件（图片 PDF）第一版不支持，会明确提示。

每次输出三份文件（默认写到 `out/contracts/`）：

| 文件 | 用途 |
| --- | --- |
| `<合同名>-review.md` | 一页纸速读版，群里直接发 |
| `<合同名>-review.docx` | Word 版，发给法务/领导批注 |
| `<合同名>-review.json` | 结构化台账，后续进多维表格/做统计 |

## 2. 报告结构

1. **合同梗概**：合同类型、我方主体、对方主体、合同内容、金额、付款方式、交付安排、期限
2. **风险清单**：按高/中/低分组，每条 = 风险标题 + 问题 + 建议 + 原文引用
3. **检查清单**：31 项固定项，逐项 ✅/❌（缺失项附补法建议）
4. **缺失/待补条款**：只列高/中风险缺失项，可直接当补条款清单用
5. **签约前必问对方的问题**：最多 10 条，业务可以直接照抄发给对方
6. **说明**：审查模式、解析字符数、复核提醒

## 3. 31 项检查清单（9 组）

| 组 | 检查项 |
| --- | --- |
| 主体 | 双方主体信息完整、签约代表授权 |
| 标的 | 名称型号、规格、数量、质量标准、交付与运输 |
| 期限 | 合同期限、生效与签署方式 |
| 价款 | 合同金额、含税与发票、付款节点与条件、对公账户 |
| 权利义务 | 双方权利义务对等、保密、知识产权归属 |
| 验收 | 验收标准、验收期限、逾期未提异议视为合格 |
| 违约责任 | 违约金比例、违约金上限、赔偿范围（是否只限直接损失） |
| 解除 | 解除条件、解除后的结算与退出、单方解除权是否对等 |
| 争议与保障 | 争议解决方式（仲裁/诉讼二选一）、管辖地是否在我方、适用法律、担保/定金/保证金、不可抗力、通知送达、附件清单、签署盖章 |

规则层能直接抓的典型坑（不依赖模型）：

- 仲裁 + 法院同时约定（约定不明）
- 按日违约金 ≥ 0.5%（年化畸高）
- 违约金总额超过合同额 30%（`CONTRACT_PENALTY_MAX_PCT`）
- 付款进入个人账户
- 管辖地不在我方所在地、且未约定「甲方所在地」
- 「一切损失/无限责任」敞口赔偿
- 「以甲方单方要求为准」这类单方标准
- 缺失验收期限、视为合格条款、违约金上限、解除后结算、担保措施等

## 4. 防幻觉的三条硬规则

1. **引用回验**：模型给的每条结论必须逐字引用原文 10–80 字，程序回查原文；查不到直接丢弃（`quote_in_text`）。
2. **规则兜底**：金额、比例、账户、管辖地这类关键结论由规则计算，不交给模型自由发挥。
3. **置信度 + 分级**：模型结论带 confidence，低于阈值降级；高风险项必须人工确认。

## 5. 权限说明（在现有机器人应用上开放/关闭）

合同审查本体是**本地解析文件**，不需要新增敏感权限。要接进飞书流程，按用途最小化授权：

| 权限 | 用途 | 建议 |
| --- | --- | --- |
| `im:message.group_msg`（敏感） | 读取客服群/合同群全部消息 | **保留**（客服闭环必需）；如只在私聊发合同可不加 |
| `im:message:send_as_bot` | 机器人发消息/卡片 | 保留 |
| `im:message`（发送+接收 @消息） | 接收 @机器人 的消息与文件 | 保留 |
| `im:resource`（如需下载群里的合同文件） | 下载聊天中的 docx/pdf 附件 | 需要时再开 |
| `im:chat:readonly` | 列出机器人所在群 | 保留（doctor 自检用） |
| `im:chat.members:readonly` | 读群成员，识别客服/客户 | 保留 |
| `bitable:app` | 工单看板、合同审查台账 | 保留 |
| `task:task:write` / `task:task:read` | 以你本人身份建飞书任务 | 已授权，保留 |
| `docx:document` / `drive:drive` | 把报告写成飞书云文档 | 需要「报告存飞书」时再开 |
| `contact:user.base:readonly` | 查用户姓名 | 可选，可关闭 |
| `calendar:*`、`okr:*`、`mail:*` | 当前用不到 | **关闭** |

原则：**能不加就不加；敏感权限（读全部群消息、读通讯录）单独审批、单独说明用途**；等真正要「读聊天文件」「写云文档」时再逐项开。

## 6. 接到机器人里的形态（下一步）

```
用户在群里发一份合同（或私聊机器人）
        ↓ 事件：im.message.receive_v1（文件消息）
机器人下载文件 → 解析 → 审查
        ↓ 30 秒内
回复一张卡片：综合风险（高/中/低）+ 高风险 3 条 + 「完整报告」按钮
        ↓ 按钮
私聊发送 Word 报告 + 建一条飞书任务给法务（截止时间可设）
        ↓
（可选）写进「合同审查台账」多维表格：合同名/对方/金额/风险等级/审查人/状态
```

## 7. 局限与边界

- **扫描件**：需要 OCR，第一版明确不支持，会提示「疑似扫描件」。
- **复杂合同**：框架协议、涉外合同、股权类合同建议法务主导，AI 只做体检清单。
- **清单不是法律标准**：31 项来自常见商业合同审阅经验，可按公司模板继续加。
- **模型可换**：任何 OpenAI 兼容接口（DeepSeek/通义/本地 vLLM）都能用，改 `.env` 即可。
- **成本**：规则模式 0 成本；模型模式一份 20 页合同约 1–3 万 token，按 DeepSeek 价格约几分钱到一毛钱。

## 8. 测试

```powershell
python -m unittest discover -s tests
```

`tests/test_contract.py` 覆盖：txt/docx 解析、清单命中/缺失、综合风险分级、仲裁冲突、按日违约金、个人账户、管辖地不误报、金额提取、引用回验、报告落盘（md/json/docx）。

## 9. 已接进机器人（contract-bot）

```bash
python -m src.cli contract-demo   # 本地模拟：发合同 → 审查 → 卡片（不连飞书）
python -m src.cli contract-bot    # 真实长连接机器人
python -m src.cli contracts       # 最近的审查记录
```

- `src/contract/bot.py`：收文件消息 → 下载 → 审查 → 回卡片；处理三个按钮（发报告 / 建任务给法务 / 忽略）。
- `src/contract/cards.py`：风险卡片（红/橙/绿），Top3 高风险带原文；帮助卡片。
- `src/contract/store.py`：SQLite 台账（`contract_reviews`），记录风险等级、报告路径、状态、任务链接。
- 权限：`im:message`、`im:message:send_as_bot`、`im:resource`、`task:task:write`；群里直接发合同还要把群加进 `CONTRACT_CHAT_IDS`。
- 测试：`tests/test_contract_bot.py`（假飞书 API，覆盖卡片、报告落盘、按钮动作、忽略、群白名单）。
